# Car Black Box on Linux — real firmware, no hardware (XC8 + SimulIDE)

This runs the **original PIC firmware** (from `lokeshkumar80/Car-Black-Box`),
unmodified except for the config word, on your Linux machine. Nothing physical
is needed:

1. **XC8** compiles the C into a `.hex` (the same file you'd flash to a chip).
2. **SimulIDE** simulates a PIC16F877A plus the LCD, buttons, RTC and a
   potentiometer, and runs that `.hex` exactly as a real board would.

Both tools are free and run natively on Linux.

---

## 1. Install the XC8 compiler

Direct download (v2.46, ~83 MB — no Microchip account needed):

```bash
wget -O /tmp/xc8-install.run \
  "https://ww1.microchip.com/downloads/aemDocuments/documents/DEV/ProductDocuments/SoftwareTools/xc8-v2.46-full-install-linux-x64-installer.run"
chmod +x /tmp/xc8-install.run
```

**This step needs root.** The installer hardcodes `/opt/microchip/xclm` for its
license manager regardless of `--prefix`, so a non-root install is not possible
— it fails with `Error creating directory /opt/microchip/xclm`.

```bash
sudo /tmp/xc8-install.run --mode unattended --unattendedmodeui none \
  --LicenseType FreeMode --prefix /opt/microchip/xc8/v2.46
```

Then put its `bin` on your PATH and check it:

```bash
echo 'export PATH="$PATH:/opt/microchip/xc8/v2.46/bin"' >> ~/.bashrc
source ~/.bashrc
xc8-cc --version        # should print the compiler version
```

(`--LicenseType FreeMode` is the free edition: full functionality, reduced
optimization. That has no effect on whether this project builds or runs.)

## 2. Install SimulIDE

SimulIDE 1.x ships as a plain tarball, not an AppImage — no FUSE involved. The
download links on <https://simulide.com/p/download110/> are generated by
JavaScript; the direct URL is:

```bash
wget -O /tmp/simulide.tar.gz "https://simulide.com/p/fls/SimulIDE_1.1.0-SR2_Lin64.tar.gz"
mkdir -p ~/opt && tar -xzf /tmp/simulide.tar.gz -C ~/opt
ln -sf ~/opt/SimulIDE_1.1.0-SR2_Lin64/simulide ~/.local/bin/simulide
simulide &            # requires ~/.local/bin on your PATH
```

No root needed. Its PIC16F877 model (`data/PIC/p16F877.mcu`) covers everything
this firmware touches: 256 B data EEPROM, ADC on PORTA0/AN0, Timer2, the MSSP
in I²C mode, and PORTD/PORTE.

## 3. Build the firmware

```bash
cd firmware
make
# If xc8-cc isn't on your PATH, point at it directly:
# XC8DIR=/opt/microchip/xc8/v2.46/bin make
```

Success produces **`firmware/dist/blackbox.hex`** — that's the file SimulIDE loads.

### From VS Code instead of the terminal

`.vscode/tasks.json` wires the same commands to keystrokes, so nothing has to be
typed:

| Task | How to run it |
|---|---|
| **Build firmware** (default) | `Ctrl+Shift+B` |
| **Build & Simulate** (default test task) | `Ctrl+Shift+P` -> *Run Test Task* |
| **Clean**, **Open in SimulIDE** | `Ctrl+Shift+P` -> *Run Task* -> pick one |

Compiler errors are parsed into the Problems panel and are clickable. The tasks
set `XC8DIR` themselves rather than relying on your `PATH`, because VS Code
tasks do not source `~/.bashrc` — so they work even if `xc8-cc` is not on the
task shell's `PATH`.

Code Runner is not useful here: it compiles and runs a single file on the host,
whereas this is a nine-file cross-compile for a PIC that then has to be
simulated. Use the tasks above.

`.vscode/c_cpp_properties.json` points IntelliSense at XC8's headers and
force-includes `pic16f877a.h`, so register and bit names (`ADCON1`, `TRISD`,
`TMR2ON`) resolve instead of showing as errors. It hardcodes the XC8 version in
its paths — edit it if you install a different one.

## 4. Open the circuit

A ready-made circuit ships with the project — just open it:

```bash
simulide firmware/blackbox.sim1
```

It is built for **SimulIDE 1.1.0-SR2** (the version installed in step 2) and
already contains the PIC, the 16x2 LCD, the six buttons with their pull-ups, the
speed potentiometer and the DS1307, fully wired. The MCU loads
`dist/blackbox.hex` automatically, so after any `make` just reopen or reset.

Press **Play** (top toolbar) to run. If the LCD stays blank, confirm the PIC's
*Frequency* property is `20 MHz` and that `dist/blackbox.hex` exists.

### Wiring it by hand instead

Only needed on a different SimulIDE version, where `blackbox.sim1` may not load.
Drop the parts below onto the canvas and connect them per the net-list. Pin names
are taken straight from the firmware's driver headers.

**Parts to place** (from SimulIDE's left-hand component tree):

- `Micro > PIC > PIC16F877A`
- `Outputs > LCD > Hd44780` (a 16×2 LCD; the LM016L equivalent)
- 6 × `Switches > Push` buttons
- 6 × `Passive > Resistor` (10 kΩ) — button pull-ups
- 1 × `Passive > Potentiometer` — the speed sensor
- 2 × `Passive > Resistor` (4.7 kΩ) — I²C pull-ups
- `Peripherals > I2C > RTC` (a DS1307-type real-time clock, if your build has one — see the note in §7)
- Power rail `+5V` and `Ground` from the top toolbar

**Net-list**

| From (PIC16F877A) | To | Notes |
|---|---|---|
| RD0–RD7 (PORTD) | LCD D0–D7 | 8-bit data bus |
| RE2 | LCD RS | register select |
| RE1 | LCD E | enable |
| — | LCD RW → GND | firmware never reads the LCD |
| — | LCD VSS→GND, VDD→+5V, VEE→GND (or via pot for contrast) | |
| RB0 | Button SW1 → GND, and RB0 → 10 kΩ → +5V | event key |
| RB1 | Button SW2 → GND, + 10 kΩ pull-up | gear up |
| RB2 | Button SW3 → GND, + 10 kΩ pull-up | gear down |
| RB3 | Button SW4 → GND, + 10 kΩ pull-up | user key (UP / login) |
| RB4 | Button SW5 → GND, + 10 kΩ pull-up | user key (DOWN / login) |
| RB5 | Button SW6 → GND, + 10 kΩ pull-up | select / enter |
| RA0 / AN0 | Potentiometer wiper (ends to +5V and GND) | **speed** input |
| RC3 | I²C SCL, + 4.7 kΩ pull-up to +5V | to DS1307 SCL |
| RC4 | I²C SDA, + 4.7 kΩ pull-up to +5V | to DS1307 SDA |
| MCLR (pin 1) | 10 kΩ → +5V | reset, held high |
| VDD (pins 11, 32) | +5V | |
| VSS (pins 12, 31) | GND | |

The buttons are **active-low**: each connects its PIC pin to GND when pressed,
and the 10 kΩ resistor pulls the pin high when released (the firmware doesn't
enable the PIC's internal pull-ups, so add them externally).

You do **not** need to draw a 20 MHz crystal: right-click the PIC → **Properties**
and set its clock/frequency to **20 MHz** directly (see §5). No external EEPROM
chip is needed either — this firmware stores the log and password in the PIC's
**on-chip** data EEPROM.

## 5. Load the hex and run

`blackbox.sim1` already does all of this. Only needed for a hand-built circuit:

1. Right-click the PIC → **Load firmware** → pick `firmware/dist/blackbox.hex`.
2. Right-click the PIC → **Properties** → set **Frequency = 20 MHz**.
3. Press the green **Power/Run** button in the toolbar.

The LCD should light up with the dashboard.

## 6. How to use it

- **Password is `2424`** (set in `main.c` at startup).
- **Speed**: drag the potentiometer — the dashboard speed (`read_adc()/10`,
  capped at 99) follows it, and speed is stored with each logged event.
- **Buttons** (roles come from `main.c`):
  - SW1 → logs a "C" event
  - SW2 → gear up, SW3 → gear down (logs the gear + speed)
  - SW4 / SW5 → from the dashboard, start **login**; inside menus they act as
    the UP/DOWN "user keys"
  - SW6 → **select / enter** the highlighted menu item
- **Menu** (after login): View Log, Clear Log, Change Password.
- A changed password lasts only until the next reset: `main()` rewrites `2424`
  into EEPROM on every boot. Upstream behaviour — see NOTES.md if you want it
  to stick.
- The log lives in EEPROM, so it survives a simulated reset (just like a real
  board keeping data across power cycles).

## 7. Known caveats (please read)

- **DS1307 in SimulIDE.** No longer a problem: 1.1.0-SR2 has a real `DS1307`
  component, and `blackbox.sim1` uses it with *Set current time at start*
  enabled, so `get_time()` reads your PC's clock over I²C. On an older SimulIDE
  without that part, the dashboard time reads wrong or as zeros and everything
  else still works — that, and only that, is the case for falling back to
  Proteus.
- **`blackbox.sim1` is version-specific.** It was generated against 1.1.0-SR2
  and verified to load there. A different SimulIDE may reject it; rebuild from
  the net-list in section 4 if so.
- **Config word added.** The upstream repo set only `WDTE=OFF` and let MPLAB X
  fill in the rest. For a command-line build and a clean sim, `main.c` here sets
  the full word (notably `FOSC=HS` for the 20 MHz crystal and `LVP=OFF`). This
  is the only change to their source.
- **XC8 Free mode** limits optimization; it has no effect on whether this builds
  or runs.

## 8. Troubleshooting

- `xc8-cc: command not found` → PATH isn't set; use `XC8DIR=/opt/microchip/xc8/<ver>/bin make`.
- Editor (not `make`) reports missing `xc.h` → `firmware/compile_flags.txt`
  hardcodes `/opt/microchip/xc8/v2.46/...`; edit it to your installed version.
- LCD shows nothing → check RE1/RE2 (E/RS) aren't swapped, LCD RW is grounded,
  and the PIC frequency is set to 20 MHz.
- Buttons do nothing → verify they pull the pin to **GND** on press and each has
  a pull-up to +5V; confirm they're on RB0–RB5.
- Speed stuck at 0 → the potentiometer wiper must go to **RA0/AN0**, ends to +5V and GND.

### What changed vs. the original repo

Two source changes: `main.c`'s config word was completed, and `init_adc()` in
`adc.c` now sets `ADCON1 = 0x8E` (so AN0 is the only analog pin, leaving RE1/RE2
free for the LCD) and selects a Fosc/32 ADC clock (Tad = 1.6 us, the minimum at
20 MHz — upstream left it at Fosc/2). See NOTES.md for the reasoning. Alongside
it, three bits of dead weight were removed: the `newfile.c/.h` duplicate files
(referenced nowhere), the `nbproject/` MPLAB X project, and the old flat layout
— the sources now live under `firmware/`. The build system was swapped from
MPLAB X's `nbproject` Makefile to a plain `xc8-cc` command line so you never
have to open an IDE — a text editor / VS Code plus `make` is enough.
